## 新功能

### 厂商识别（离线 OUI 库）

- IEEE MA-L / MA-M / MA-S 三张注册表共 **54,190 条**（1.68 MB），编译期嵌入，
  运行时零 I/O、零第三方依赖
- 按 9 / 7 / 6 个十六进制位**最长前缀优先**匹配
- 全零、组播（I/G）、本地管理（U/L）地址一律不查——查不到就留空，不猜
- 数据来自 IEEE 官方 CSV，由 `tools/oui-gen/gen_oui.py` 确定性生成，可复现

### MAC 地址获取（ARP）

- Windows：`GetIpNetTable2`（手写 FFI，结构体布局断言钉死）
- Linux / Android：`/proc/net/arp`
- 只接受单播 MAC；仅补空缺、不覆盖已有值
- 扫描一结束自动补全一次——ARP 表此时才可能有目标条目

### 主机名反查

- `getnameinfo` + `NI_NAMEREQD`，独立线程 + 超时，**按需单条发起**（绝不批量阻塞）
- 结果规整：去尾点、拒 IP 字面量、剥 NetBIOS 数字后缀；带否定缓存
- TUI 按 `n` 对当前行反查；GUI 每行一个「反查」按钮

### 结果快照与恢复

- 每轮扫描结束**自动落盘**一份快照（Android 上进程会被系统随时回收，不依赖退出钩子）
- 下次启动若发现上次结果，弹确认框：丢弃 / 暂不恢复 / **恢复结果**——默认不恢复
- 同一份结果只询问一次（指纹机制），不会每次启动都弹
- 严格解析：签名 / 版本 / 列数 / 行数 / 状态任一不符即报「快照损坏」，绝不猜测性修补

## 导出

CSV / TXT 新增「厂商」「主机名」两列，**追加在末尾**（旧列位置不变）。
厂商名含逗号时按 RFC 4180 转义；TXT 定宽排版按显示宽度截断（CJK 感知）。

## 实测结果（真实局域网，Windows 原生 ICMP）

```text
目标：127.0.0.1, 192.168.0.1, 192.168.0.95, 192.168.0.229, 192.168.0.255, 8.8.8.8
扫描完成：total=6 online=3
邻居表：ok=true 条目=5 补上 MAC=3 补上厂商=1

127.0.0.1       在线                                              XuanKui
192.168.0.1     在线      5C:7D:AE:EA:CD:8D   zte corporation
192.168.0.95    超时      E2:7B:18:8E:06:56                       ← 本地管理地址，无厂商是正确行为
192.168.0.229   在线      BE:51:D2:EE:26:F0                       ← 同上
192.168.0.255   超时                                              ← 广播，无 MAC 是正确行为
8.8.8.8         超时
```

真实数据抓出并修复了两个单测抓不到的 bug：`SOCKADDR_INET` 按整型读取导致 IP
字节序颠倒（`192.168.0.1` 曾显示成 `1.0.168.192`）；广播 MAC 曾随 `.255` 目标
混进结果表。
